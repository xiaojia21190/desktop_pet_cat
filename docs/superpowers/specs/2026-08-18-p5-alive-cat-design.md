# P5 活过来的猫 · 触发层激活设计（alive-cat）

日期：2026-08-18
状态：已确认（用户逐节确认范围/方案/6 节设计后落档）
前置：P1-P4 已全部完成（见 `docs/plans/2026-08-17-smart-companion-redesign.md` 四期总览）

## 背景与诊断

用户反馈："现在感觉都没什么作用，都不太会触发。" 代码核查证实这不是错觉——触发链路大面积死亡：

1. **静音时段全覆盖夜间活跃时段**：默认静音 23:00–8:00，而用户是夜间活跃型。P4 旗舰意图 `night_owl_care` 触发窗口 23:00–1:00 被静音判断（`reaction_policy_engine.gd:36` 位于判定链最前）完整覆盖，**数学上永不触发**。LLM 模式同样被 controller 静音拦截直接 return。
2. **45 秒清零杀死所有长时意图**：`context_collector.gd:33-37` 中停止输入超 45 秒 `_continuous_active_seconds` 归零。真实工作节奏（打字→读代码/思考→再打字）永远凑不齐 30/45/60 分钟的"不间断活跃"门槛。深夜关怀、久坐提醒、写代码鼓励三个意图全部不可达。
3. **LLM 系统性沉默**：用户已配 LLM（perception/llm/smart 全开），但决策提示词写明 "Most of the time a cat does NOT talk... choose react: false"，LLM 忠实执行安静；规则引擎在 LLM 模式下降级为"仅供参考"。两头都哑。
4. **零调用死代码**：`build_fail_streak` 意图等待的 `report_build_result()` 全项目零调用者，纯死代码。
5. **产品从未进入真实使用循环**：真实存档显示 `total_play_time=1123 秒`（约 19 分钟）、interaction_stats 全零（head_pat/food_given/wand_given 均 0）——道具与互动系统做完至今未被使用过一次。

结论：地基（心理层/感知/记忆，P1-P4）是好的，问题在"最后一公里"的触发层与激活层。

## 产品决策（与用户确认的关键选择）

- 方向选 A「让猫活过来」：不加新系统，修触发层 + 激活已有能力。
- 存在感节奏不替用户猜：做成 5 档配置开关（安静/低频/中频/高频/智能）。
- 范围选"全部一起做"：收尾未提交批次 + 触发层 + 道具激活，按方案一三段流水线交付。

## 三段流水线总览

```
P5a 落袋为安：验收并按逻辑拆提交工作区约 790 行未提交改动 + 素材
P5b 让猫活过来：存在感档位 + 三处死链修复 + LLM 双轨节奏
P5c 道具激活闭环：首次引导 + 猫主动邀请 + 亲密度反馈钩子
```

依赖关系：P5b 的存档/UI 改动与未提交批次文件重叠（main.gd / settings_panel.gd / save_manager.gd / smart_pet_controller.gd），必须先 P5a 清地基；P5c 依赖 P5a 的 bond_system 与 P5b 的档位机制。

## P5b 让猫活过来

### 存在感档位（中央旋钮）

新设置项 `presence_level`（0-4），取代名不副实的 `reminder_intensity`（现只影响久坐阈值）：

| 档位 | 值 | 定位 | 节奏目标 |
|---|---|---|---|
| 安静 | 0 | 纯氛围宠物 | ≤1 句/小时，仅硬提醒（久坐、胜利） |
| 低频 | 1 | 关键时刻陪伴 | 1~3 句/小时（饭点、深夜、摸鱼抓包） |
| 中频（默认） | 2 | 工位同事 | 每 10~15 分钟一句闲聊/小动作 |
| 高频 | 3 | 话痨猫 | 分钟级，主动撩你、邀请互动 |
| 智能 | 4 | 免手动 | 工作时自动压低、摸鱼/休闲时正常，感知驱动；感知关闭时退化为中频 |

档位驱动三层：

1. **规则模式**：意图解锁白名单 + 冷却倍率（安静 ×4、中频 ×1、高频 ×0.5）；安静档砍掉闲聊类意图。
2. **LLM 模式**：决策周期按档（安静 180s / 低频 90s / 中频 45s / 高频 20s）+ 提示词注入档位人设。
3. **意图解锁**：安静 [欢迎/久坐/胜利]；低频 + [饭点/深夜/摸鱼]；中频 + [闲聊/天气]；高频 + [主动邀请/扔东西]。

关键决策：

- 读档迁移：旧 `reminder_intensity` 映射 low→低频、medium→中频、high→高频；新档落地后旧键从设置面板与存档删除。
- 静音时段是硬顶，与档位正交（档位管"多话"，静音管"何时闭嘴"）。
- 智能档第一版从简：工作类活动（coding/writing）压低冷却倍率，娱乐类正常；不做复杂调度器。
- 档位切换即时生效。

### 短平快新意图（挂在档位白名单上）

| 意图 | 触发条件 | 档位 |
|---|---|---|
| 饭点提醒 | 12:00-13:00 / 18:00-19:00 且活跃 | 低频+ |
| 摸鱼抓包 | 感知到 browsing/video 且此前有 coding 时段 | 低频+ |
| 天气闲聊 | 每小时首决策，模板句 | 中频+ |
| 主动邀请 | 长时间无互动（>30 分钟），猫邀请撸猫/玩道具 | 中频+（P5c 扩展克制机制） |
| 扔东西 | chaos 高时把毛线球扒拉下桌 | 高频 |

摸鱼抓包、扔东西消费心理层与感知数据——四期地基首次串成闭环。

### 死链修复

**① 深夜关怀被静音覆盖 → 分层静音**

- 通用规则：**软静音 = 静音时段的前 60 分钟（进入缓冲），其余为硬静音**。默认 23:00–8:00 时即 23:00–24:00 软、0:00–8:00 硬；设 2:00–8:00 时即 2:00–3:00 软、3:00–8:00 硬——跨午夜与否都成立。
- 软静音内允许轻关怀类意图（深夜关怀、晚安），气泡淡入淡出、不播庆祝音；硬静音真静默，quiet_mode 仅在此返回。
- 深夜关怀触发条件放宽：软静音时段内 + 滑窗活跃累计 30 分钟。
- LLM 模式放行软静音（现 controller 直接 return，连问都不问 LLM）。

**② 45 秒清零 → 滑动窗口累计**

- 停止输入 ≤5 分钟视为思考间隙：按 50% 折算计入连续活跃；超 5 分钟才清零。
- 参数（5 分钟、50%）为 presence_level 关联常量，不新增设置项。
- `_active_by_hour`（习惯画像数据源）同步用新口径，保证夜猫子记忆台词数据真实。

**③ 构建连败死代码 → 删除**

- 删除理由：设想接 IDE/CI 但产品定位是本地进程名级感知，永无数据源；体验价值由 LLM 模式（activity=coding + 长时 + 心理推断"卡住了"）与高频档「主动邀请」（猫看你 coding 很久没互动过来蹭你）覆盖。
- 删除范围：reaction_policy_engine 的 streak 判定、main.gd 的 `_build_failure_streak` 计数器、`report_build_result()` 及相关事件。

### LLM 双轨节奏（终结系统性沉默）

```
轨道A 保底心跳（规则引擎复活）：
  规则引擎按 presence_level 节奏独立判定
  → 命中意图：动作 + 模板台词立即上（不等 LLM）
  → 同时异步发 LLM 润色请求（模板台词 + 人设 + 一句话上下文，超时 5s）
  → 润色回来且气泡仍在显示则替换；超时/失败用模板（用户无感）

轨道B LLM 自主（周期放权）：
  每 llm_tick（20~180s 按档）全上下文决策
  → 提示词按档位重写人设（安静猫/关键时刻/工位同事/话痨猫/自适应）
  → 沉默反压：payload 注入 silent_streak（连续沉默次数），
    "You have stayed silent for the last N cycles" 催开口
  → silent_streak 同时喂规则引擎：高频档 LLM 连续沉默时主动触发邀请顶上
```

- 规则引擎从"降级参考"升回"保底大脑"——LLM 挂/超时/无 key 时猫照样按档位说话（回归"规则主导、LLM 润色"原则）。
- 润色请求独立小 prompt，不带全上下文，快且省 token。
- 档位提示词人设表：

| 档位 | 注入 system prompt 的人设 |
|---|---|
| 安静 | 只在真正重要的时刻说话（久坐/胜利），每小时最多 1 句 |
| 低频 | 关键时刻开口：饭点、深夜、久坐；每小时 1-3 句 |
| 中频 | 工位同事，每 10-15 分钟自然插一句；摸鱼时可温和吐槽 |
| 高频 | 话痨猫，几乎每次决策都要有表现，主动邀请互动 |
| 智能 | 按当前活动自适应（工作→克制，摸鱼→活泼），提示词告知活动类别 |

### 修复后意图可达性（预期）

| 意图 | 修复前 | 修复后 |
|---|---|---|
| 深夜关怀 | 永不触发 | 软静音内滑窗活跃 30 分钟即触发 |

## P5c 道具激活闭环

### 闭环结构

```
入流① 首次引导        入流② 猫主动邀请(高频/智能档)   入流③ 日常钩子
        │                       │                        │
        ▼                       ▼                        ▼
用户第一次撸猫/喂食    猫叼毛线球到屏幕中央邀请    bond +4/+5 → 升级气泡
        │                       │                  + 解锁进度可见
        └───────────────────────┴────────────────────────┘
                                ▼
                 bond_system 升级 → 解锁动作 + 品种
                                ▼
                 猫的动作库随亲密度变丰富（可感知的成长线）
```

### 入流① 首次引导（一次性，非弹窗轰炸）

- 首次启动（存档无 `first_interaction_done`）：启动 30 秒后猫走到屏幕中央偏下，气泡「摸摸我吧」+ 头顶呼吸光效 10 秒；完成首次撸猫/喂食 → 标记落存档，气泡回应。
- 第二步（首次互动后 10 分钟内，仅一次）：猫叼逗猫棒「点我有惊喜」引向快捷菜单。
- 全程无模态弹窗、无教程遮罩——猫自己说话引导，符合"猫发起"调性。

### 入流② 猫主动邀请（挂档位）

- 中频及以上、距上次互动 >30 分钟、猫非睡眠：每决策周期约 15% 概率触发；形式随机：蹭屏幕边缘探头 / 叼道具到屏幕中央 / 尾巴扫任务栏。
- 台词走 LLM 润色；低 affection 时台词傲娇化（心理层接入）。
- **克制机制**：用户忽略 → 冷却翻倍累积（30→60→120 分钟），三次忽略后本日内不再邀请——尊重"不想被打扰"。

### 入流③ 日常钩子

- `add_bond` 成功时气泡右上浮「亲密度 +4」小提示（复用 smart_line_bubble 轻量模式）。
- 设置面板/悬浮面板加亲密度进度条（等级 + 进度 + 下一级解锁预告）。
- 喂食在 energy < 40 时 bond ×1.5（饿的时候喂更亲，道具有策略性）。

### 边界（不做的事）

- 不加新道具类型（现有 5 种先验证循环）。
- 不做每日任务/签到（下一步再说）。
- 不做离线成长（桌宠直觉）。
- bond 只涨不跌（现有设计），affection 继续承担"当下态度"，两套数值不混。

## 完成后的世界（P5 整体成功标准）

猫开机即活：按所选档位主动出现，深夜写代码被关怀，摸鱼被温和吐槽，饭点被提醒；第一次用就知道怎么互动，互动喂进只涨不跌的亲密度，解锁动作和品种；LLM 在场时台词有灵气，LLM 不在时模板兜底照样有性格——「都不太会触发」成为历史。
